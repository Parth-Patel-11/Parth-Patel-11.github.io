AES Request Decrypt Helper

A generic debugging tool for apps that use hybrid RSA+AES encryption on requests/responses. Capture a request → auto-scrape crypto fields → decrypt the request & response bodies (AES-GCM / AES-CBC). Everything runs 100% locally in your browser.

How this pattern works: many apps generate a random AES key per request, encrypt the body with it (IV sent in a header such as x-iv), then wrap that AES key with the server's RSA public key into a header such as x-encrypted-key. The RSA-wrapped key can only be opened by the server's private key — so to decrypt locally you need the plaintext AES key from the app's memory. The one-time hook below captures it for you.

1 · Setup

Get the target app and your tooling ready before anything else.

  1. Open the target app and log in (use only apps/accounts you own).
  2. For a persistent hook, install the Tampermonkey extension. For a quick/temporary hook, you'll just use the browser Console (F12) — no install needed.
  3. Open DevTools (F12) → Console, and check the crypto lib: type typeof CryptoJS. "undefined" = WebCrypto (this tool's hook/sniffer fit). "object" = the app uses CryptoJS and needs a different hook.

2 · Auto-header hook script

Install this before capturing any request. It grabs each request's AES key and attaches it as an x-debug-key header, so the copied request already contains the key and step 3 auto-fills it.

  1. Persistent: Tampermonkey → New script → paste → edit the @match line to your target site → save → reload the app.
  2. Quick/temporary: paste into the Console, Enter. Works until you reload.
  3. Verify: after one request, run window.__DBG_AES_KEY in the Console — it should print a base64 key.
⚠ x-debug-key exposes the plaintext key in your own captured requests — a debugging aid. Use it only on apps/accounts you own, keep captures private, and remove the hook when done.
